# 30.5 — Phase 4: Gemini multimodal triage

> **Written after the code.** Phase 4 connected CareGrid AI to the Gemini API: the
> `triage-v3` prompt, the validated output contract, the ten deterministic safety
> rules, the sanitisation boundary, the keyword fallback engine, image validation
> by byte signature, the `aiRuns` audit trail, and the citizen-facing triage panel.
>
> **This document records what was built, the six real bugs the tests found, the
> places the code and the documentation had to be reconciled, and what was
> deliberately NOT built.** It follows [30.2](./30.2_PHASE_2_IMPLEMENTATION.md) and
> [30.4](./30.4_PHASE_3_FOUNDATION.md), because a phase record nobody wrote is a
> phase nobody can audit.
>
> **A note on the phase number.** docs/30 §6 calls Phase 4 "Database + incidents"
> — the create pipeline, the lifecycle table, the duplicate engine. Those are
> **not** in this build and are not claimed to be. The brief for this build is the
> authority on sequencing and says "Gemini AI Multimodal Emergency Triage"; the
> documentation is the authority on identifiers. See §5 D-1.

---

## 1. What Phase 4 is, in one paragraph

A citizen describes an emergency, optionally attaches a photo, and presses
"Analyse with AI". The request passes through the Phase 3 pipeline, and the
report is sanitised, delimited and bounded before it crosses to Google. Gemini
returns a fixed 17-field JSON object, which is validated against a `.strict()`
schema — so an injected `dispatch: true` is a validation failure rather than a
triage decision — then passed through ten deterministic rules that can **raise**
urgency and can never lower it, can never invent a casualty count, and can never
let a diagnosis the reporter did not use reach a screen. The result is editable by
the citizen, labelled as the AI's opinion everywhere it appears, and filed as AI
metadata on the run record. If any of it fails, a pure keyword engine produces an
honest triage offline, the report is still submitted, and a person reviews it.

## 3. The request path, in order

```
POST /api/ai/triage
  ↓ withRequest          rate limit (20/h) → authenticate → validate
  ↓ requireCapability    r13_readAiTriagePanel
  ↓ validateImage        SIGNATURE first, then declared type, extension, size
  ↓ toTriageRequest      the sanitisation boundary (docs/09 §4)
  ↓ getTriageProvider    gemini | gemini-mock | unconfigured
  ↓ sanitiseForModel     9 steps. Scores BEFORE neutralising.
  ↓ buildUserContent     untrusted text in <citizen_report>, never in the system turn
  ↓ callGemini           quota guard → SDK call → retry 429/503 → translate
  ↓ parseAndValidate     JSON.parse → aiTriageOutputSchema.safeParse
  ↓ repair (once)        only the Zod ISSUE PATHS go back, never the prior response
  ↓ normalizeTriageOutput  R1–R10. Raises urgency, never lowers.
  ↓ logAiRun             best-effort. A failure here cannot lose the report.
  ↓ response             + outcome, attempt, simulated, mediaDropped, aiRunId
```

### 3.1 The one ordering that is load-bearing

`sanitiseForModel` scores the suspicion **before** neutralising markers, and
`normalizeTriageOutput` runs R8 (the diagnosis filter) **before** R2 (the
trapped-person rule), and R2 searches the **original text** rather than R8's
output. All three orderings were found by a test failing, and each one was
inverting a safety rule. They are documented at their call sites and asserted
in `tests/unit/ai/sanitize.test.ts` and `tests/unit/ai/rules.test.ts`.

## 4. The six real bugs this phase found

Each was found by writing a test, and each is now pinned by one. **Five were in
code written in this phase**, which is worth stating plainly: the tests did not
find pre-existing defects, they found defects introduced two hours earlier.

### 4.1 The suspicion score ran AFTER the neutraliser, so the easiest attack scored zero

`sanitiseForModel` computed `suspicionScore` from the final text. The neutraliser
*rewrites* `ignore previous instructions` into `ignore_previous_instructions`, so
the canonical override — the single most common attack — was scored **0**, and
only phrasings the rewriter missed scored. R7 caps confidence at 0.4 above a
score of 3, so the effect was exactly inverted: the easiest attack got the
highest confidence.

*Fixed by* scoring the normalised text, before the rewrite. The two properties —
DETECTION and MITIGATION — are now independent. *Pinned by*
`tests/unit/ai/sanitize.test.ts` "is the SAME for the same text, twice".

### 4.2 R2 searched R8's OUTPUT, so a trapped person could stay `low`

`not breathing` is in both tables. When the reporter used the phrase, R8 kept it
and R2 raised urgency. When the model introduced it, R8 stripped it as an
invented diagnosis — and R2 then searched the stripped summary, found nothing, and
left the urgency alone. Two rules interacted to erase the evidence for the
emergency.

*Fixed by* searching the reporter's original text plus the landmarks. *Pinned by*
`tests/unit/ai/rules.test.ts` R2 cases and "does NOT strip when the original text
is unavailable".

### 4.3 R8 with no original text deleted the reporter's own words

Related, and worth its own entry because it is the more dangerous direction.
R8's test is "was this phrase in the report?" — with no report to check against,
every diagnosis term looks invented, and the rule stripped them all. Given
`originalText: ''` and a summary of "The person is not breathing", the clause
vanished.

*Fixed by* treating an absent original as **not verifiable**, not **invented**:
the phrase is kept and the record is flagged. *Pinned by* the same file.

### 4.4 The WebP signature would have rejected every real WebP

The table checked 12 contiguous bytes, including the RIFF **file-length field** at
offset 4–7. A real photograph has a non-zero length, so it failed. A validator
that also masked the field to zeros would fail identically.

*Fixed by* a two-region signature (`bytes` + `tail` at an offset), so the length
is not checked at all. *Pinned by* `tests/unit/ai/media.test.ts`, which tests
four different length values and asserts a WAV is rejected.

### 4.5 The JPEG mask accepted only the `Exx` family

Masking the fourth byte to `0xF0` accepts JFIF (`E0`) and EXIF (`E1`) and rejects
`DB` (DQT), `C0`–`CF` (SOFn) and `EE` (Adobe) — all real, all common.

*Fixed by* checking the three-byte `FF D8 FF` prefix and no more. *Pinned by* a
test that tries seven markers, including the two the broken mask would have
rejected.

### 4.6 `shapeSummary` could store 241 characters

In the no-space path the candidate was already at 240 and the terminating period
was appended after the trim. *Fixed* by capping **after** assembly, which is the
only ordering arithmetic on two paths cannot get wrong.

### 4.7 Two more, found by the same suites

- **`RESOURCE_CATALOGUE_LOOKUP(reason)`** — a const object called as a function,
  with `reason` passed where `resourceId` belonged. Every resource would have been
  capped as inferred.
- **`bytes[i] as number & mask`** — `as` binds tighter than `&`, so this parsed as
  a *type*. TypeScript caught it; the note is in the code because the
  "fix" of removing the parentheses silently changes the comparison.

## 5. The reconciliations

### D-1 — "Phase 4" means different things in the brief and in docs/30 §6

docs/30 §6 Phase 4 is "Database + incidents". The brief is Gemini. **The brief won
the sequence**, and docs/30 §6's create pipeline, lifecycle table and duplicate
engine are **not** built and are not claimed to be. docs/34 §4 already recorded
them as not-present.

### D-2 — The brief's category list is wider than the anchor's

The brief §6 lists 13 categories including `crime_security`, `rescue`,
`utility_failure`, `building_hazard`, `road_hazard`, and an `unknown` urgency.

**docs/09 §5.1 won.** It is a T0 anchor, and DOCUMENTATION_INDEX §1 says code
that disagrees with T0 is wrong. The anchor has 11 categories
(`violence_crime`, not `crime_security`; `infrastructure`, not
`utility_failure`/`building_hazard`; no `unknown` urgency) because those values
are already the **Firestore taxonomy** in `types/enums.ts` and are enforced by
`firestore.rules` and `config/categories.ts`. Introducing a second vocabulary
would mean an AI category that no rule and no config table knows.

The brief's own wording — "**Recommended** categories", "Create a strict schema
**similar to**" — reads as deferring to the specification, and this is the
deference. `tests/unit/ai/schema.test.ts` asserts the *brief's* values are
REJECTED, and says why in the test: a rejected value is visible, a silently mapped
one is not, and "close enough" is how two urgencies come to be treated as one.

### D-3 — The fallback stopped returning nulls, and a Phase 3 test was corrected

Phase 3's `fallbackOutcome` returned `category: null, urgency: null,
confidence: null` and a test asserted it. docs/09 §7.2 specifies a keyword engine
and §7.3 promises "every incident gets a plausible, honest triage even with zero
AI availability".

**The test was corrected, not deleted** — the docs/30.4 §5.2 precedent, where a
test was corrected *because an anchor document says it was wrong*. The correction
is **stronger**: it now asserts every value is inside the controlled taxonomy, that
confidence is below the review threshold, that `needsReview` is always true, and
that the summary says on its face that it is automated. The original test's
*intent* — never fabricate — is preserved, because derived-from-the-report is not
the same as invented.

### D-4 — The repair call lives in the adapter, not the service

docs/09 §3 assigns repair to `services/ai/triage.ts`. It is in
`services/integrations/gemini/index.ts`, because the repair is a *second Gemini
call with a Gemini-shaped prompt*, and `TriageProvider` is deliberately a
three-method interface (docs/34 §1.3). Widening it to expose a second call would
make the seam something a provider author can use to run arbitrary generations —
the exact property that keeps "just ask the model to dispatch someone" from being
a one-line addition. `aiRuns.attempt` records which attempt produced the result.

### D-5 — `client.ts` exists, so `gemini.ts` does not

docs/09 §2 says `services/ai/gemini.ts` is the only file that may change when the
SDK major version changes. Phase 3 recorded the naming as
`services/integrations/gemini/{index,client}.ts` (docs/34 §1.1) because the
security check forbids `process.env` in `index.ts` and the transport and the
policy have different rules. The version-pinning promise is honoured by
`client.ts` + `index.ts` being the only two files that import `@google/genai`.

### D-6 — The mock is a separate provider, not a branch

brief §26 asks for `AI_MOCK_MODE`; docs/32 MUST 7 and
`scripts/security-check.cjs` forbid a `NODE_ENV`/`DEV` success branch in an
integration. **Both are satisfiable**: `isAiMockMode()` in `lib/env.server.ts`
returns `true` only when the flag is set AND `NODE_ENV !== 'production'` AND no
`GEMINI_API_KEY` is present. `index.ts` reads no environment at all and contains
`MockTriageProvider`, whose canned response goes through the **same** validation
and the **same** rules, whose values are deliberately unexciting (`other`/`low`/
0.3), and whose `providerName` is `gemini-mock` so the API reports
`simulated: true`. A new check verifies the refusal is in the code, and
`serverEnvProblems()` reports it as a **fault** so it is visible, not silent.

   **types** (`GenerateContentParameters`, `GenerateContentConfig.responseSchema`,
   `SafetySetting`, `Part.inlineData`, `Candidate.finishReason`) and its
   `models.generateContent` is **never executed**. Everything either side of that
   call is tested with an injected transport; the call itself is not. This is the

   asserts the properties from source and **lists what that cannot cover** at the
   bottom of the file.
4. **Image validation was tested with synthetic headers**, not real photographs.
   The signatures are the documented ones, but a real JPEG from a real phone has
   not been through it.

## 10. Known limitations, stated rather than discovered later

| # | Limitation | Consequence | Where it is recorded |
| --- | --- | --- | --- |
| 1 | **The SDK call is never executed in this environment** | A signature or option-name mistake in `client.ts` would only surface with a real key | §6.1 |
| 2 | Two schemas describing the same 17 fields, cross-checked by a test rather than derived | A field added to one and not the other fails `schema.test.ts`, but the fix is manual | `services/ai/schema.ts` header — Zod 4 exposes constraints as opaque class instances, so a converter would depend on internals and return an unconstrained schema, which is the same silent failure reached by a more respectable route |
| 3 | The keyword engine is English-only | A report in Hindi or Telugu falls back to `other`/`low` with confidence 0.25 | `fallback.ts`; the real model handles them, and the fallback is the degradation path |
| 4 | The keyword engine misclassifies when a generic term ties a specific one | `"feeling unwell due to extreme heat"` scored `medical` until multi-word phrases were added to the tables | `tests/unit/ai/fallback.test.ts` — a class of bug that recurs when a reporter phrases something the tables do not know |
| 5 | The panel is not rendered in a browser | A layout or runtime error in the component would not be caught here | `ai-triage-panel.test.ts` lists the boundary |
| 6 | `AI_MOCK_MODE` is honoured whenever there is no key and it is not production | A developer could demo with a mock without noticing | Refused in production, reported as a fault by `serverEnvProblems()`, and labelled `simulated` in the API response |
| 7 | `images[]` base64 in a JSON body is not the eventual design | The real path is a signed URL plus a Storage download (docs/15) | `validators/ai.ts` documents the 7 MB per-image and 3-image bounds; the Storage path is Phase 5 |
| 8 | The local RPM/RPD guard is per-instance | It does not survive a cold start, so the project quota can still be exceeded across a burst of instances | `client.ts` — it is explicitly NOT the abuse control; `lib/server/rate-limit.ts` is, and it is Firestore-backed |
| 9 | Phase 3's rate-limit ordering compromise (D-4 in 30.4) is still open | A caller with no permission can burn another subject's quota | Unchanged; still Phase 5's to close with `POST /api/incidents` |

**Do not delete these.** They are the honest boundary of what has been verified.
